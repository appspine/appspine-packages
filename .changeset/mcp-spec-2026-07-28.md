Migrate the MCP server package to the 2026-07-28 protocol contract and MCP SDK v2.

The package now serves modern stateless requests through `createMcpHandler` and the Node
adapter while retaining legacy stateless compatibility during the transition period. Consumers
should deploy the compatible gateway before upgrading downstream apps and keep the legacy path
available until rollout verification is complete. The package also declares the Prisma runtime
peer required by its exported authentication and audit integration modules.

## Breaking: `POST /mcp` now requires an explicit Host/Origin allowlist

The v2 SDK's inbound Host and Origin validation is fail-closed: every consuming app **must**
set `MCP_ALLOWED_HOSTNAMES` (and, if the frontend/agent traffic sends an `Origin` header,
`MCP_ALLOWED_ORIGIN_HOSTNAMES`) to the app's real externally-reachable hostname(s) before or
immediately after upgrading. An app that upgrades and redeploys with either variable unset
gets an empty allowlist, and `POST /mcp` starts returning `403` for every call -- n8n, AI
agents, and the gateway's own outbound calls all break, with no startup-time error to signal
why. `.env.example` in the app template only sets these to `localhost`, which is correct for
local dev but not for a deployed environment; **set the real hostname explicitly per
environment before rollout, not just at .env.example's default.**
